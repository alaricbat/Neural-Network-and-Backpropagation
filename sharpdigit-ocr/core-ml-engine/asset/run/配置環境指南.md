# macOS C++17 專案建置與除錯指南

## 1. 開發環境

本專案使用以下環境：

- 作業系統：macOS，Apple Silicon（arm64）
- IDE：CLion
- C++ 標準：C++17
- 編譯器：Apple Clang 16 或 Homebrew GCC 16
- 建置工具：CMake
- 平行運算：OpenMP

> **重要原則：** 編譯器、標準函式庫、OpenMP 與 CMake 建置設定必須相互匹配。建議使用 CMake 管理多個 `.cpp` 檔案，不要只手動編譯 `main.cpp`。

---

## 2. 問題一：GCC 標準函式庫編譯錯誤

### 錯誤訊息

```text
error: '__c_file' has not been declared
error: '_M_cfile' was not declared in this scope
```

錯誤位置：

```text
/opt/homebrew/Cellar/gcc/16.2.0/include/c++/16/
aarch64-apple-darwin23/bits/basic_file.h
```

### 原因分析

錯誤發生於 GCC 標準函式庫的內部標頭檔，可能與編譯器安裝、標頭檔配置或工具鏈相容性有關。不能僅憑這些訊息就確定 GCC 本身有缺陷。

### 解決方式

先確認目前使用的編譯器：

```bash
which g++
g++ --version

which clang++
clang++ --version
```

本次環境的 Apple Clang 為：

```text
Apple clang version 16.0.0
Target: arm64-apple-darwin23.6.0
```

可以先使用 Apple Clang 建立獨立的建置目錄，測試另一套工具鏈。

---

## 3. 問題二：CMake 無法找到 Ninja

### 錯誤訊息

```text
CMake was unable to find a build program
corresponding to "Ninja".
CMAKE_MAKE_PROGRAM is not set.
```

### 原因

CMake 被指定使用 Ninja，但系統找不到 Ninja 執行檔。

### 解決方式 A：使用 Unix Makefiles

```bash
cmake -S . -B cmake-build-appleclang \
  -G "Unix Makefiles" \
  -DCMAKE_C_COMPILER=/usr/bin/clang \
  -DCMAKE_CXX_COMPILER=/usr/bin/clang++
```

如果系統缺少 `make`，請先確認 Command Line Tools 是否已安裝。

### 解決方式 B：安裝 Ninja

```bash
brew install ninja
ninja --version
```

兩種方式選擇一種即可。

### 注意事項

CMake 的建置目錄會記錄 Generator。已經使用 Ninja 初始化的目錄不能直接改成 Unix Makefiles。

建議使用新的目錄，例如：

```text
cmake-build-appleclang/
```

這樣就不需要刪除原本的建置資料。

## 4. 問題三：Apple Clang 找不到 OpenMP

### 錯誤訊息

```text
Could NOT find OpenMP_CXX
(missing: OpenMP_CXX_FLAGS OpenMP_CXX_LIB_NAMES)
```

### 原因

Apple Clang 通常需要額外的 OpenMP 執行環境，不能假設系統已經提供完整的 OpenMP 開發套件。

### 解決方式

先安裝 Homebrew 的 OpenMP 套件：

```bash
brew install libomp
```

確認安裝位置：

```bash
brew --prefix libomp
```

Apple Silicon 的常見位置為：

```text
/opt/homebrew/opt/libomp
```

接著在 CMake 設定時，指定 OpenMP 的標頭檔、編譯參數與動態函式庫：

```bash
cmake -S . -B cmake-build-appleclang \
  -G "Unix Makefiles" \
  -DCMAKE_C_COMPILER=/usr/bin/clang \
  -DCMAKE_CXX_COMPILER=/usr/bin/clang++ \
  -DOpenMP_C_FLAGS="-Xpreprocessor -fopenmp -I$(brew --prefix libomp)/include" \
  -DOpenMP_CXX_FLAGS="-Xpreprocessor -fopenmp -I$(brew --prefix libomp)/include" \
  -DOpenMP_C_LIB_NAMES=omp \
  -DOpenMP_CXX_LIB_NAMES=omp \
  -DOpenMP_omp_LIBRARY="$(brew --prefix libomp)/lib/libomp.dylib"
```

這是本次成功使用的配置方式。若 Homebrew 安裝路徑或套件版本不同，請以實際路徑為準。

### CMake 設定

```cmake
find_package(OpenMP REQUIRED)

target_link_libraries(core_ml_engine PRIVATE
    OpenMP::OpenMP_CXX
)
```

這樣 CMake 就能將 OpenMP 的編譯與連結設定套用到目標程式。

## 5. 問題四：TxtMatrixReader 出現 Undefined symbols

### 錯誤訊息

```text
Undefined symbols for architecture arm64:
  "TxtMatrixReader::TxtMatrixReader(int)"
  "TxtMatrixReader::read(std::string const&) const"
  "vtable for TxtMatrixReader"
```

### 原因

原本執行的指令是：

```bash
g++-16 -std=c++17 -fopenmp main.cpp -o run/main
```

這個指令只編譯 `main.cpp`，沒有把 `TxtMatrixReader.cpp` 加入編譯及連結。

`main.cpp` 可以看見 Header 中的函式宣告，但連結器仍需要找到實際的函式定義。

### 解決方式 A：手動編譯所有必要的實作檔

```bash
mkdir -p run

g++-16 -std=c++17 -fopenmp \
  -I include \
  main.cpp \
  src/Matrix.cpp \
  src/ReLU.cpp \
  src/Softmax.cpp \
  src/MultilayerPerceptron.cpp \
  src/TxtMatrixReader.cpp \
  -o run/main
```

此指令假設檔案路徑與本專案一致；若還有其他實作檔，也必須加入。

### 解決方式 B：使用 CMake

建議將所有必要的實作檔加入 `CMakeLists.txt`：

```cmake
add_executable(core_ml_engine
    main.cpp
    src/Matrix.cpp
    src/ReLU.cpp
    src/Softmax.cpp
    src/MultilayerPerceptron.cpp
    src/TxtMatrixReader.cpp
)
```

接著執行：

```bash
cmake --build cmake-build-appleclang
```

這樣就不需要每次手動列出所有 `.cpp` 檔案。

### 為什麼還會出現 vtable 錯誤？

`TxtMatrixReader` 繼承自 `IMatrixReader`，而父類別包含純虛擬函式 `read()`。

當 `TxtMatrixReader` 的虛擬函式定義沒有正確連結進來時，可能連帶出現 vtable 相關錯誤。因此，應先檢查 `.cpp` 是否加入建置目標，再檢查函式簽名是否一致。

## 6. 建議的日常建置流程

### 第一步：設定專案

```bash
cmake -S . -B cmake-build-appleclang \
  -G "Unix Makefiles" \
  -DCMAKE_C_COMPILER=/usr/bin/clang \
  -DCMAKE_CXX_COMPILER=/usr/bin/clang++
```

如果此目錄已經完成設定，通常不需要每次重新執行。

### 第二步：編譯

```bash
cmake --build cmake-build-appleclang
```

### 第三步：執行

```bash
./cmake-build-appleclang/core_ml_engine
```

### 第四步：遇到錯誤時的檢查順序

1. 確認實際使用的編譯器。
2. 確認 CMake Generator 與建置目錄一致。
3. 確認 OpenMP 已安裝並正確連結。
4. 確認所有必要的 `.cpp` 都加入 `add_executable()`。
5. 確認函式宣告與定義的簽名完全一致。
6. 使用 `--verbose` 檢查實際編譯與連結命令。

---

## 7. 最後的建議

對於包含 `Matrix`、`ReLU`、`Softmax`、`MultilayerPerceptron` 和 `TxtMatrixReader` 的 C++ 專案，建議：

- 以 CMake 作為唯一主要建置入口。
- 在 CLion 中使用 `cmake-build-appleclang` 作為對應的建置目錄。
- 不要在同一個建置目錄混用 GCC 與 Apple Clang。
- 新增 `.cpp` 檔案時，記得加入 CMake 目標。
- 遇到連結錯誤時，先檢查實際連結命令，而不是直接修改 C++ 標準版本。

**核心原則：編譯器負責編譯每個實作檔，連結器負責將它們組合成最終程式，而 CMake 負責管理整個流程。**
